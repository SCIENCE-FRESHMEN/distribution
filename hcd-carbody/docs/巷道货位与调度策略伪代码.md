# 车身库巷道、货位与调度策略伪代码

本文档依据当前 `D:\hcdcarbody` 源码编写，说明车身库改进巷道分配、单层货位选择、启发式调度和优化调度的主要分支与循环。行号以本次更新后的工作区为准；后续代码增删后应优先使用“文件 + 类/函数名”定位。

车身库与纵梁库的主要差异是：货位为单层；巷道容量可不同；入库任务未携带 `production_line` 时不能预知最终出库产线；出库按巷道配置的 `skuId` 或特征字段匹配，并受入/出库口可用性和产线当前组限制。

## 1. 改进巷道选择

入口：`allocation/proposed_strategy.py`，`ProposedAisleAllocator.allocate()`，第 92-290 行。

```text
输入：task_info、inventory_positions

循环：统计全部物理空货位（第 114-120 行）
    empty_by_aisle[aisle] += 1，仅统计 pos.is_empty() 的单层货位

循环：统计每条巷道的入库预占（第 122-143 行）
    pending_inbound_by_aisle：已进入核心待处理队列的任务
    pending_execution_tasks：已下发、等待 EXECUTING 反馈的任务
    running_tasks：已反馈执行中但未完成的任务
    三类任务均计入 pending_by_aisle，防止同一空位被重复承诺

effective_empty[aisle] = max(0, empty_by_aisle - pending_by_aisle)（第 145-150 行）
usable_capacity = 排除禁用位后的巷道容量（第 152-154 行）
effective_ratio = effective_empty / usable_capacity（第 155-162 行）

available_aisles = effective_empty > 0 且巷道启用（第 164-171 行）
分支 1：核心提供入库规则（第 173-178 行）
    调用 _get_valid_inbound_aisles(task, production_line)
    过滤 skid_type、禁入配置、巷道状态等规则不允许的巷道
分支 2：没有候选巷道（第 180-181 行）
    返回 None

future_loads = _compute_future_outbound_loads()（第 183-185 行）

分支 3：match_mode == features（第 189-198 行）
    feature_loads = _compute_feature_aisle_loads(task)
    用同匹配特征的在库量抑制库存集中
否则：feature_loads 均为 0

循环：最近选择窗口（第 200-205 行）
    统计每个候选巷道最近 self._recent_select_window 次被选择的次数

循环：计算每条候选巷道综合分（第 207-247 行）
    capacity_score = capacity_ratio_weight * effective_ratio
    future_penalty = future_weight * future_load
    feature_penalty = feature_weight * feature_load
    分支 4：workload_time_weight > 0
        用预计工作秒数与最小工作秒数之差计算 workload_penalty
        不再叠加按任务数量计算的 pending_penalty
    否则：pending_penalty = pending_weight * pending_by_aisle
    recent_penalty = recent_weight * recent_selected_count
    total_score = capacity_score - future_penalty - feature_penalty
                  - pending_penalty - workload_penalty - recent_penalty
    记录 [PROPOSED_AISLE_SCORE] 原始值、各项贡献和总分

candidate_aisles = total_score 最大的全部巷道（第 249-252 行）
分支 5：最高总分并列（第 253-272 行）
    先选择近期选择次数最少的巷道
    仍并列时按轮询指针 _rr_index 决定，避免长期偏向小巷道号

记录 selected_aisle 到最近选择双端队列并返回（第 272-290 行）
```

未来负载计算在 `_compute_future_outbound_loads()`（第 442-501 行）：它从各产线 `current_group` 起读取前 `self._future_n` 个计划任务，按出库匹配模式、巷道可服务范围和特征约束累计压力。它不读取未传入 API 的未来任务明细，因此不会以未知实际任务作为评分输入。

关键辅助过程：


## 3. 启发式调度

入口：`schedule/heuristic.py`，`HeuristicScheduler.solve()`，第 88-354 行。

```text
输入：inbound_tasks、outbound_tasks、running_tasks、current_time
aisle_task_count = 各巷道 running 任务数量（第 111-120 行）

循环：出库任务按生产组过滤（第 128-152 行）
    group_idx = task.group_idx；缺失时从任务 ID 解析
    仅保留 group_idx == production_line_current_group 的任务

循环：逐条当前组出库任务（第 155 行起）
    读取任务生产线的匹配模式和 match_fields
    循环候选库存位置：校验 skuId 或特征字段、巷道出库口可用性、FIFO 顺序
    按巷道汇总可直接出库的位置
    分支 1：没有可执行位置
        跳过，不向队列写入任务
    否则：选择当前 aisle_task_count 最小的巷道
        FIFO 启用：优先最早 _inbound_time；同时间再按列号偏好排序
        复制 TaskData，冻结 assigned_aisle 和 positions，追加到该巷道任务序列
        aisle_task_count[aisle] += 1

循环：逐条入库任务（第 270 行起）
    已有完整 positions：复用
    否则：调用入库巷道分配器和货位分配器
    仅当巷道与完整 positions 均有效时追加到序列

返回 {aisle: [TaskData, ...]}
```

车身库的入/出库口状态由 `WarehouseCore` 维护。出库候选检查会读取当前巷道对应 `out_line` 的可用性；因此即使库存匹配，指定出库口禁用或拥堵时，该巷道也不会作为当前任务的可执行位置。

## 4. 优化调度

入口：`schedule/optimizer.py`，`OptimizationScheduler.solve()`，第 53-148 行。

```text
heuristic_solution = HeuristicScheduler.solve(...)
filtered_outbound = _filter_outbound_tasks()       // 第 260-273 行，当前生产组过滤
feasible = _compute_feasible_assignments()         // 第 297-397 行，候选巷道、位置和数量
solutions = _generate_solutions()                  // 第 417-466 行，采样并去重

分支 1：solutions 为空
    返回 heuristic_solution

heuristic_future_ready = _calc_future_ready_outbound(heuristic_solution)
best = _evaluate_and_select_best(solutions, heuristic_solution, heuristic_future_ready)
返回 best
```

`_build_sampled_solution()`（第 705-930 行）的主要流程：

```text
将当前生产组的出库任务与其他入/出库任务混合
循环直到两侧任务均耗尽：
    一侧耗尽：顺序追加另一侧
    两侧都有：80% 概率先处理入库，20% 概率先处理出库
    while 条件保证所有任务都被遍历；概率仅改变本样本的先后顺序

循环：current_group_tasks + mixed_tasks_list
    任务没有 feasible 或候选为空：跳过
    出库：优先从空闲、出库口可用且不拥堵的巷道抽样
    无优先候选：排除拥堵巷道后，按 1/(1+local_task_count) 加权选择
    入库：从可行巷道按局部负载选择
    选择位置后复制 TaskData，冻结位置和巷道，写入 aisle_task_sequences
    local_task_count[aisle] += 1

循环：各巷道序列
    紧急入库任务稳定前置；其他任务保留样本内相对顺序
```

`_evaluate_and_select_best()`（第 963-1153 行）的主要流程：

```text
循环：每个去重候选（第 981-1007 行）
    priority = 候选中各出库任务对应的 future_ready 累计值
    balance = _calculate_line_progress_balance_score(solution)

循环：候选生成抽样权重（第 1013-1026 行）
    base_w = 1 / (max_tasks + 1)^2
    ready_factor = 1 + 0.5 * normalized_priority
    balance_factor = 1 / (1 + 0.01 * balance)
    sampling_weight = base_w * ready_factor * balance_factor

前 5 个最高权重候选直接进入精细评分（第 1034-1048 行）
循环：剩余候选无放回加权抽样（第 1058-1095 行）
    总权重为 0 时改用均匀概率
    每选中一个候选，同时删除其局部下标与权重

循环：进入精细评分的方案（第 1101-1151 行）
    base_score, details = WarehouseCore.get_sol_score(solution)
    choice_bonus = _calculate_outbound_choice_bonus(solution)
    score = base_score + choice_bonus
    空方案加 10000 分
    输出 [OPT_SCHEDULE_SCORE]，保留仿真原始指标、加权项与最终分数
    选择 score 最小的方案

返回 best_solution
```

`_calc_future_ready_outbound()`（第 521-595 行）以“当前库存 + 候选方案中的入库/出库影响”模拟各产线可连续完成的出库数量。它使用任务 SKU 与 `match_fields` 构造匹配单元，不能仅按 SKU 数量替代特征匹配；其结果只影响候选抽样优先级，不直接替代最终的事件仿真评分。
