# 纵梁库巷道、货位与调度策略伪代码

本文档依据当前 `D:\hcd` 源码编写，覆盖改进巷道分配、改进货位分配、启发式调度和优化调度的主要决策分支。行号以本次更新后的工作区为准；后续代码增删后应优先按“文件 + 类/函数名”定位。

## 1. 改进巷道选择

入口：`allocation/proposed_strategy.py`，`ProposedAisleAllocator.allocate()`，第 73-213 行。

```text
输入：task_info、inventory_positions
读取 task_id、skus、production_line、每根梁的 match_fields 属性

分支 1：任务没有 SKU（第 96-99 行）
    返回 None；不将没有物料信息的任务随机分配到巷道

valid_aisles = 全部巷道
循环：对任务携带的每个 production_line 求可服务巷道交集（第 110-132 行）
    未携带 production_line：该 SKU 不增加服务范围约束
    一个 production_line：其服务范围适用于任务内全部梁
    多个 production_line：按 SKU 槽位逐一应用
    valid_aisles = valid_aisles ∩ 当前产线可服务巷道

分支 2：交集为空（第 134-137 行）
    返回 None；两根梁不能绕过配置被拆分到不同巷道

simulated_positions_by_aisle = 真实货位副本 + pending/running 入库模拟占位（第 143-151 行）
valid_aisles = 仅保留模拟后仍有可用货位的巷道

分支 3：候选巷道为空（第 153-156 行）
    返回 None

分支 4：单梁（第 158-181 行）
    按 beamSide 放入对应的左/右槽位，另一槽位为 None
    调用 _allocate_with_urgency_comparison()，按配对紧急度和候选巷道状态选巷道

分支 5：天然配对双梁（第 183-195 行）
    条件：sku_pairs[sku1] == sku2
    调用 _balance_by_sku_distribution()
    优先在已有对应 SKU 分布且库存结构更平衡的巷道落位

分支 6：非天然配对双梁（第 197-213 行）
    调用 _allocate_with_urgency_comparison()
    先比较两根梁分别进入各巷道后形成可配对出库机会的紧急程度
    再按候选巷道的可用状态排序，返回最佳巷道
```

模拟货位视图由 `_get_simulated_positions_for_aisle()`（第 228-258 行）和 `_build_simulated_positions_by_aisle()`（第 260-284 行）构建。它不会修改真实库存，而是复制每条巷道货位后叠加已承诺入库；因此连续调用分配器时，不会把同一空层再次推荐给 pending 或 running 任务。

## 2. 改进货位选择

入口：`allocation/proposed_strategy.py`，`ProposedPositionAllocator.allocate()`，第 830-917 行。

```text
输入：inventory_positions、task_info、可选 current_position
读取 assigned_aisle、skus、sku_ids、各 SKU 的 match_fields 属性

分支 1：无 SKU 或尚未分配巷道（第 846-853 行）
    返回 []

positions = assigned_aisle 的全部货位（第 855-858 行）
positions = simulate_pending_positions_for_aisle(...)（第 860-868 行）
preferred_level = _get_default_preferred_level(current_position)（第 870-872 行）

分支 2：第一个槽位为单梁 [SKU, None]（第 878-886 行）
    根据 beamSide 确定 home_row 和 guest_row
    调用 _allocate_single_beam_flexible()
    优先选择同排已有配对梁的可写对侧层；没有时才选择独立空层

分支 3：第二个槽位为单梁 [None, SKU]（第 888-896 行）
    与分支 2 相同，但使用第二个 SKU 的 beamSide

分支 4：天然配对且属性相同（第 898-904 行）
    pos = _find_best_empty_slot(...)
    返回 [pos, pos]
    两个元素表示同一双层货位：后续库存写入时按 SKU 槽位分别写 upper/lower，
    不代表只为双梁任务分到一个半组位置

分支 5：非天然配对，或 match_fields 属性不一致（第 906-912 行）
    调用 _allocate_double_constrained()
    为两根梁分别选位置；第二根梁排除第一根已占用的具体层位

分支 6：未形成完整位置集合（第 914-917 行）
    返回 []，不允许返回只有一根梁位置的半组结果
```

关键辅助过程：

```text
simulate_pending_positions_for_aisle()（第 920-1018 行）
    复制当前巷道货位
    循环 pending_inbound_by_aisle、pending_execution_tasks、running_tasks
        仅处理 assigned_aisle 与当前巷道相同的入库任务
        调用 _apply_simulated_inbound() 写入副本
    返回模拟视图

_get_levels_per_column()（第 1155-1202 行）
    Tcol = 堆垛机移动 1 列的二维物理时间
    二分查找最大 n，使移动 n 层的物理时间不超过 Tcol
    返回 n；若 1 层已慢于 1 列，则返回 Tcol / Tlevel

_find_best_empty_slot()（第 1469-1516 行）
    过滤 disabled、reserved 和不可写货位
    用列号优先模式确定 preferred_column
    按 (列偏离, 层偏离, 行号, 列号, 层号) 排序，返回首个空层

_find_nearest_empty()（第 1575 行起）
    对目标梁的对侧候选空层计算列层等价距离
    distance = |column - target_column| + |level - target_level| / levels_per_column
    以 distance、列优先和层偏好依次排序，返回最近可写位置

_allocate_double_constrained()（第 1403-1467 行）
    先找第 1 根梁候选
    循环第 2 根梁候选并排除与第 1 根相同的实际层位
    只有两根梁均有合法位置才返回；否则返回 []
```

## 3. 启发式调度

入口：`schedule/heuristic.py`，`HeuristicScheduler.solve()`，第 45-325 行。

```text
输入：inbound_tasks、outbound_tasks、running_tasks、current_time
aisle_task_count = 每条巷道的 running 任务数（第 74-82 行）

循环：过滤出库任务是否属于产线当前组（第 84-118 行）
    优先读取 task.group_idx
    否则从 OUTBOUND_PLx_GPy_... 任务 ID 解析组号
    仅保留 group_idx == production_line_current_group 的任务
    无法解析的旧格式任务保留，后续由库存与货位规则再过滤

循环：逐条当前组出库任务（第 120 行起）
    单梁：遍历 get_sku_positions(sku)，按 SKU 与 match_fields 筛选位置
    双梁：遍历候选位置组合，要求两根梁满足配对及属性约束
    按巷道汇总合法 positions
    分支：没有合法位置
        跳过任务
    否则：优先选择 aisle_task_count 最小的巷道
        FIFO 启用时调用 _select_outbound_position() 按入库时间选择
        复制 TaskData，冻结 assigned_aisle 与 positions，追加到巷道序列
        aisle_task_count[aisle] += 1

循环：逐条入库任务（出库处理完成后）
    已冻结 positions：直接复用
    否则：依次调用入库巷道分配器和货位分配器
    仅当巷道和完整货位集合同时有效时写入序列

返回 {aisle: [TaskData, ...]}
```

FIFO 判断在 `_fifo_enabled()`（第 327-338 行），位置排序在 `_select_outbound_position()`（第 398-419 行）。同一入库时间的候选位置，再由 `position_column_preference_mode` 作为次级排序依据。

## 4. 优化调度

入口：`schedule/optimizer.py`，`OptimizationScheduler.solve()`，第 58-143 行。

```text
heuristic_solution = HeuristicScheduler.solve(...)
filtered_outbound = _filter_outbound_tasks()          // 第 258-295 行，生产组过滤
feasible = _compute_feasible_assignments()            // 第 297-398 行，预计算任务可行巷道/位置
solutions = _generate_solutions()                     // 第 428-484 行，生成去重随机样本

分支 1：没有可行候选方案
    返回 heuristic_solution

best = _evaluate_and_select_best(solutions, heuristic_solution)
返回 best
```

`_sample_single_solution()`（第 863-1112 行）的主要流程：

```text
构造 mixed_tasks_list（第 963-988 行）
循环直到入库和出库列表均耗尽：
    一侧耗尽：追加另一侧任务
    两侧均有任务：80% 概率先追加入库，否则先追加出库
    概率只改变本样本的处理顺序；while 条件保证每个任务都会被轮到

循环：current_group_tasks + mixed_tasks_list（第 990 行起）
    任务没有 feasible 或没有可行位置：跳过
    出库：优先从空闲且未拥堵的可行巷道中，按当前局部负载加权选择
    无优先候选：对出库剔除下游拥堵巷道，再按 1/(1+local_task_count) 选择
    未选中位置：跳过
    否则：复制任务、冻结巷道和位置、写入 aisle_task_sequences
            local_task_count[aisle] += 1

循环：各巷道已形成序列（第 1104-1110 行）
    将紧急入库稳定前置，其他任务保持相对顺序
```

`_evaluate_and_select_best()`（第 1125-1304 行）的主要流程：

```text
循环：每个去重候选方案（第 1146-1168 行）
    计算 future_ready 连续出库收益
    计算产线推进均衡度，供候选抽样使用

循环：生成抽样权重（第 1174-1188 行）
    base_w = 1 / (1 + max_tasks)^2
    ready_factor = 1 + 0.5 * normalized_future_ready
    balance_factor = 1 / (1 + 0.01 * progress_balance_penalty)
    weight = base_w * ready_factor * balance_factor

前 5 个最高权重候选直接进入精细评分（第 1197-1208 行）
循环：其余候选无放回加权抽样（第 1215-1246 行）
    权重和为 0：退回均匀概率
    每次抽中后同步移除候选和权重，防止重复评分

循环：最终选中的候选（第 1257-1300 行）
    base_score, details = WarehouseCore.get_sol_score(solution)
    bonus = _calculate_outbound_choice_bonus(solution)
    score = base_score + bonus
    空方案额外加 10000 分
    保留 score 最小的方案

分支 2：启发式基线评分更小
    返回 heuristic_solution；否则返回采样最优方案
```
